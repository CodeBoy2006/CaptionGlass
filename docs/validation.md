# 开发顺序与验收计划

## M0：可编译、可回放的开发骨架

执行 `./gradlew :engine:check :app:assembleDebug :app:lintDebug`。核心检查不需要 Android 设备或模型，使用单个 executable Kotlin check，失败即非零退出。Android 构建需要 JDK 17、SDK 36 和已接受的 SDK 许可。

核心验收覆盖：稳定原文不提前提交未完成句、最终文本只提交一次、重复 revision 不制造稳定性、最长等待、源修正显式报告、队列有界、单一 active、上下文有界、旧会话/错误 revision/重复返回无效、超时/停止状态、1,000 个确认片段的完整性计数、阅读最短停留及显示积压。

UI smoke：启动应用 → 两种方向分别播放固定文本 → 检查原文先出现、译文整句出现 → 中途停止 → 记录保留已确认片段及状态 → 重新开始清空旧演示 → 旋转/暗色/大字无阻塞性遮挡。模拟数据结果不用于性能宣传。

捕获 smoke：拒绝录音权限、取消 projection、成功授权、静音等待、播放可捕获声音、通知停止、系统撤销、重新授权启动。检查结束后没有 active projection、AudioRecord 或前台通知。仅在选定测试设备操作，不能把模拟器信号检测当作手机覆盖率。

## M1：第一条真实中英字幕链

### 实现顺序

1. 固定原生依赖与 CPU 构建，先离线文件逐段跑 ASR/MT，检查许可证、哈希、端点和 cancellation。
2. 建立真实语速音频回放入口，按采样时钟喂音频，同时记录每个阶段的时间；不能用尽快离线跑完替代实时回放。
3. 接入服务及 10–20 秒有界 PCM 缓冲，验证 16 kHz 输入、可用设备格式及重采样，不因 VAD 丢词首尾。
4. 补齐 source correction 和语言规则、MT watchdog、失败状态消费，阻止孤儿 JNI 任务。
5. 添加原生 View 悬浮窗：双语、拖动把手、触摸模式、横竖屏位置、安全区与字体缩放。身体文字穿透和任意位置交互不能同时开启。

### 必须通过的检查

- 一套模型完整匹配，无不同 checkpoint 文件混用；断网可识别和翻译。
- 任意时刻 ASR/MT 各一个活动工作器；取消、重启、旧回调、失败能重复执行。
- 所有已确认片段都有翻译或明确原因；错误修正有事件记录；原文/译文可分别计时。
- 不能捕获时给出可观察事实，授权结束时即时释放；拒绝权限不崩溃。

## M2：30–60 分钟可持续体验

实现 Room 记录的用户选择、保留周期与删除；DataStore 设置；TXT/SRT/VTT 导出并明确会话时间轴；相关术语筛选；语言包下载/离线导入/失败回退。状态数据库不能在异常时无限缓存到内存，存储失败应明确报告并采取可恢复行为。

同一批有使用权的样本覆盖讲课、技术专名、中英混说、快语速、口音、背景音乐、数字和否定。至少选择一台主流骁龙中端、一台天玑中端和一台旗舰，同时播放视频。

| 指标 | 记录方式 | 初始目标 |
| --- | --- | --- |
| 原文首次可读 | 语音开始 → 首个可读假设，P50/P95 | 0.8/1.2 秒 |
| 译文稳定延迟 | 片段结束 → 完整译文，P50/P95 | 1.5/2.5 秒 |
| 完整体验延迟 | 片段开始 → 完整译文 | 包含语义等待，独立报告 |
| MT 吞吐余量 | 平均 MT 耗时 / 平均片段到达间隔 | ≤0.6 |
| 持续积压 | 队列长度、最老片段年龄、热稳态趋势 | 30–60 分钟不持续增长 |
| 完整性 | 已确认、已翻译、未翻译及其原因 | 每个片段可核对 |
| 阅读稳定 | 已显示字符修订量、重排、停留、阅读积压 | 人工检查与事件统计 |
| 内存/热量/电量 | 峰值 PSS、热状态与耗电；冷/热启动分开 | 8GB 机 PSS 初始预算 2.5–3GB |

上述数字来自产品材料，是可修订验收目标，没有实测达标声明。存储原始音频默认关闭，质量数据集需明确授权并放在仓库之外；性能日志默认只记 ID、时间和计数。

对照遵守一次只换一项：固定 ASR 比 MT、固定 MT 比 ASR、固定两模型比提交/显示策略。语种扩展单独验收，不能从英语 WER 推导日语效果。任何轻量配置需验证数字、否定、专名和术语约束，并记录模型/内核/设备组合。

## M3：已验证语言与性能扩展

通过长时实测后再评估 STQ、白名单加速、日语及其他语种。热策略在片段边界切换且有冷却；找不到已验证的轻量配置时显示原文与未翻译状态，绝不隐式请求云端。
